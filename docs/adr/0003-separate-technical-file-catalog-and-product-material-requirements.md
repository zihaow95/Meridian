# 技术文件目录与产品材料要求分层治理

Project Meridian 将受控文件配置拆为两层：系统管理员发布技术文件目录，负责格式、大小、预览、敏感等级和保存约束；产品总监发布产品材料要求模板，按产品分类和生命周期状态将材料标记为 `REQUIRED`、`OPTIONAL` 或 `NOT_APPLICABLE`。相比单一文件配置，该方案需要维护两类版本及引用关系，但能保持平台管理权与业务材料决策权分离，并允许后续调整必填要求而不改写历史；上传材料必须归入明确类型和业务对象，不提供无边界的“其他附件”。当前有效材料必须上传，可靠历史材料追加到不可覆盖版本链，无法确认版本顺序、有效状态或来源的文件只能作为待整理资料保留，不能直接成为正式有效版本。具体关键文件版本由对应部门负责人或专业确认人确认，产品总监在关键材料确认和完整性检查通过后确认并发布老品基线，不代替专业确认。
