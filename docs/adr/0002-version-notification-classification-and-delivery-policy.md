# 通知分类与投递策略采用版本化配置

Project Meridian 将通知类别、通知等级及排序、模板默认分类、确定性等级升级、渠道、投递时机和重试规则统一纳入发布后不可覆盖的配置版本，业务调用方只提交业务事实，不能自行指定等级或钉钉渠道。通知配置由系统管理员复用现有配置编辑、校验和发布能力维护，不新增管理员角色；启用超级管理员双人复核时，发布必须由另一名管理员复核，且配置权限不赋予敏感业务数据读取权。相比代码常量或各模块独立判断，该方案需要维护配置发布与历史版本绑定，但允许后续调整而不分叉规则，并能审计每条通知采用的模板和策略；配置只允许受控条件，不执行任意 Python、SQL 或用户脚本。
