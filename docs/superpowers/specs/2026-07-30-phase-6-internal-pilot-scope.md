# Project Meridian 阶段6内部闭环与试用准备范围

**状态：** 范围、退出标准与任务级计划已确认，尚未开始实现  
**确认日期：** 2026-07-30

## 目标

完成现有产品、受控文件、站内通知、试用认证和反馈管理的内部闭环，通过开发验证、代码审阅和阶段验收形成阶段6 GO 基线；阶段7完成生产化与发布收尾后，再启动真实业务用户试用。尚未具备外部条件的钉钉或 API 集成不阻塞阶段6。

## 已确认范围

### 存量产品与受控文件

- 首批现有产品不超过20个，全部通过既有产品创建流程逐一录入；
- 不为首批试用建设产品主数据 Excel 批量导入，也不建立第二条产品创建入口；
- 逐一录入同时承担既有产品档案、版本、SKU和渠道模块的业务回归，发现的问题进入试用反馈闭环；
- 可以上传并导入项目成员提交的现有文件，将其纳入受控版本、权限、审计和业务对象关联；
- 受控文件采用双层配置：系统管理员维护技术文件目录，产品总监发布产品材料要求模板；
- 产品材料要求模板按产品分类和生命周期状态将材料标记为 `REQUIRED`、`OPTIONAL` 或 `NOT_APPLICABLE`，发布后不可覆盖，调整发布新版本；
- 首批已上市产品默认必填产品规格、内外包装图片、标签稿、营养标签/营养成分文件和检测报告；
- 其他经技术文件目录允许的材料可以上传，但必须选择明确材料类型、敏感等级、所属产品/版本/SKU、文件日期和来源；不提供无限堆放的“其他附件”类别；
- 材料完整性强调相关、分类明确、来源清楚和权限正确，不以无差别增加文件数量为目标；
- 当前有效材料必须上传；能够确认版本号、日期和来源的历史文件按时间顺序追加到不可覆盖版本链；
- 无法确认版本先后、有效状态或可靠来源的文件进入待整理区，保留原文件和来源证据，但不能直接标记为正式有效版本；
- 不要求业务人员为补全历史伪造版本号、日期、批准人或确认记录；
- 待整理资料补齐来源和版本信息后，仍须由材料类型对应的部门负责人或专业确认人确认具体文件版本；产品总监只在关键材料确认和完整性检查通过后确认并发布老品基线，不代替专业人员判断文件内容；
- 历史资料来源是成员主动提交的副本，不扫描个人设备，不把个人目录视为系统权威数据源；
- 当前没有统一外部业务系统，不建设虚构 API、通用集成平台或桌面采集代理；
- 导入必须保留来源、提交人、时间、文件校验值、处理结果、重复/冲突和待处理履历。

#### 首批文件验收数据基线

- 首批覆盖不超过20个产品，至少录入100个正式受控文件版本；
- 正式受控文件中至少包含20个能够确认版本顺序、有效状态和来源的历史版本；
- 另准备至少10个待整理资料，验证其保留来源证据但不能被误设为正式有效版本；
- 单文件大小上限由已发布技术文件目录配置，阶段六试用默认值为50MB，不得硬编码为永久规则；
- 首批试用文件总量按不超过2GB准备；
- 以上数字是阶段六功能与业务验收的数据基线，不是系统永久容量上限；正式容量、安全和恢复验证仍属于阶段7。

### 站内通知闭环

- 站内通知是完整、可追踪的权威通知记录；
- 沿用已经确认的通知类别、通知等级、版本化模板和通知策略；
- 补齐通知列表、未读/已读、待办深链接、处理同步、关闭和审计；
- 通知摘要只做最小披露，点击后实时判权；
- 阶段六不调用任何钉钉能力。

### 试用能力与启动准备

- 阶段6只完成非生产环境中的试用能力、数据和反馈闭环验证，不组织真实业务用户正式试用；
- 试用系统部署在指定设备，通过公司局域网地址访问，不开放公网入口；
- 管理员为每位试用人员预置独立的临时账号和密码，禁止多人共享账号，并保留角色权限、账号停用和登录审计；
- 试用页面明确标识“非生产试用环境”，本地账号认证不得被描述为生产认证方案；
- 钉钉登录完成后不自动删除本地账号能力，是否保留由届时的实际运行、安全和应急登录需求另行评估；未经正式批准，本地账号认证不得在生产环境启用；
- 阶段7 GO 后启动首轮真实用户试用，默认约8人、持续2周：产品总监1人担任试用验收负责人，产品经理2人且其中1人统一收集反馈，研发、质量/合规、包装/设计、销售/渠道和系统管理各1人；
- 试用部门、参与人、周期和反馈责任人均为可调整的批次配置，不得硬编码；调整不改写已完成试用批次的参与人、反馈和验收记录；
- 各专业代表验证本领域数据和文件，系统管理员只负责账号、配置和环境支持，不代替业务验收；
- 提供可重复初始化的试用数据和业务主流程；
- 建立问题反馈、严重程度、复现证据、处理状态和验收结果记录；
- 业务可试用不代替质量门禁，也不等于生产上线。

## 阶段6退出与 GO 标准

- 格式、静态与类型检查、MySQL迁移、后端与前端测试、OpenAPI、阶段6 E2E和全量工程门禁实际通过；
- 完成首批产品和文件验收数据基线，并跑通材料配置、上传、历史版本、待整理资料、专业确认和老品基线发布；
- 六类通知和三级通知等级均有测试证据，站内通知生成、未读/已读、深链接实时判权、业务处理同步、关闭和审计形成闭环；
- 至少验证一个敏感文件越权拒绝场景，以及系统管理员不能凭配置权限读取敏感业务内容；
- 使用内部验收数据完成一条“创建反馈—分级—修复—复测—关闭”闭环；
- P0和P1缺陷必须为零；P2只有在存在明确规避方案、责任人、目标版本并获得项目负责人书面接受时才可遗留；P3可进入后续清单；
- 保存阶段6测试矩阵、代码审阅结论、全量门禁结果、已知限制和阶段检查点；
- 钉钉、真实外部API、正式容量、备份恢复、生产部署和真实用户试用不属于阶段6 GO 条件。

## 明确延期

- 钉钉登录、组织同步、钉钉通知和钉钉深链接；
- 真实外部系统 API 接入；
- 通用集成平台、个人设备扫描或自动采集；
- 阶段7负责的安全容量、备份恢复、离线发布和生产部署。

## 后续顺序

阶段6完成开发、代码审阅和 GO 验收后进入阶段7；阶段7完成安全、容量、备份恢复、发布和部署收尾并 GO 后，再启动真实用户首轮试用。
